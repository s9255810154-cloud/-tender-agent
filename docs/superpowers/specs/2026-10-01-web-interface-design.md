# Веб-интерфейс тендер-агента — Этап 1: «Загрузил ТЗ → получил смету»

Дата: 2026-10-01

## Контекст и цель

Проект `tender-agent` перенесён из чат-сессии claude.ai в Claude Code
(см. `README.md`, `CLAUDE.md`). Вся логика расчёта (извлечение ТЗ через
Claude API, сопоставление с прайс-листами, сборка Excel-сметы) написана и
частично проверена на реальных данных, но доступна только как разрозненные
Python-скрипты, часть из которых считает по РЕАЛЬНЫМ зафиксированным
данным уже выигранных контрактов (см. `mlrz_smeta_export_v2.py` — хардкод
реального ФОТ и ставок ₽/м² из Приложения №1 конкретного договора).

Цель Этапа 1 — дать нескольким коллегам внутри компании простой веб-доступ
к расчёту сметы для **нового** тендера (где реальных цен ещё нет, нужна
оценка по нормативам), без необходимости трогать код.

Явно вне объёма Этапа 1 (решено в брейнсторминге):
- публичный доступ из интернета — сервер на управляемой облачной
  инфраструктуре (Caddy-прокси на фиксированные порты), открытие новых
  портов/доменов требует отдельного явного подтверждения и, вероятно,
  действий на стороне провайдера (TWC1). Делаем локально сейчас, хостинг —
  отдельная задача;
- сбор тендеров с ЕИС/Контур.Закупки (Этап 2, отдельный брейнсторминг);
- выбор среди ~15 старых `*_smeta_export.py` — используется только новый
  универсальный путь через `smeta_builder.py`;
- автоматизация проверки формул через `recalc.py` (LibreOffice headless) —
  проверка глазами, автоматизируем только при реальной необходимости;
- pytest-тесты — в проекте их нет нигде, не вводим ради одного модуля.

## Архитектура

Два новых файла в корне `Projects/tender-agent/`, поверх существующего кода
без его изменения:

```
tender-agent/
├── smeta_pipeline.py   # НОВОЕ: универсальный конвейер ТЗ → смета (оценка по нормативам)
├── app.py               # НОВОЕ: Streamlit-интерфейс
├── Outputs/              # (локально в проекте) сюда сохраняются сгенерированные .xlsx
│   └── (создаётся pipeline-ом, напр. tender-agent-smeta/<object_name>_<timestamp>.xlsx)
└── ...существующий код без изменений (tz_extraction.py, smeta_builder.py,
      knowledge_base.py, document_ingestion.py, matcher.py, resolver.py,
      price_parser.py, unit_price.py, supplier_fallback.py)
```

Технология: **Streamlit** — выбран вместо FastAPI+HTML (вдвое больше
кода ради того же результата) и вместо Telegram-бота (ближе к Этапу 2).
Однофайловый Python UI, из коробки: загрузка файла, кнопка скачивания,
спиннер, метрики — без отдельного frontend-слоя.

## Компонент 1 — `smeta_pipeline.py`

Связывает существующие модули в один вызов для НОВОГО объекта (такого
сквозного пути сейчас нет — только per-объектные скрипты с реальными
зафиксированными числами). Основная функция:

```python
@dataclass
class SmetaPipelineResult:
    xlsx_path: str
    object_name: str
    region: str
    area_sqm: float
    cleaning_days: int
    contract_months: int
    staff_count: int
    staff_count_source: str       # из process_extraction()
    fot_month: Optional[float]    # None, если норматив не найден
    materials_unresolved: list[str]
    warnings: list[str]           # человекочитаемые предупреждения для UI

def generate_smeta(
    file_path: str,
    *,
    region: str = "Москва",
    object_complexity: str = "стандартный",
    schedule_complexity: str = "комбинированная смена (ежедневная-основная + ежедневная-поддерживающая, один сотрудник)",
    vat_rate: float = 0.20,
    output_dir: str = "Outputs/tender-agent-smeta",
) -> SmetaPipelineResult:
    ...
```

Шаги внутри:
1. `document_ingestion.ingest_document(file_path)` → `IngestedDocument`.
   Если `full_text` пуст/слишком короткий (скан без текстового слоя,
   OCR не справился) — `raise PipelineError("Не удалось извлечь текст из документа...")`.
2. `tz_extraction.extract_tz_structured(doc)` — живой вызов Claude API
   (уже проверено вживую в этой сессии). Исключения `anthropic.*` не
   глушатся — пробрасываются с понятным сообщением наверх, в UI.
3. `tz_extraction.process_extraction(extraction)` → `ExtractedObjectSummary`
   (`area_sqm`, `cleaning_days`, `contract_months`, `staff_count`,
   `staff_count_source`, `tz_items`). Если `extraction["contract_periods"]`
   пуст — `raise PipelineError("В документе не найдены объёмы услуг по периодам...")`.
4. ФОТ: `knowledge_base.get_combined_shift_salary(region, object_complexity, schedule_complexity)`.
   Если `None` — `fot_month = None`, в смете строка ФОТ помечается как
   "не найден норматив — введите вручную", в `warnings` добавляется текст
   с указанием, для какой комбинации регион/сложность/график норматив
   отсутствует (эксперт видит, что именно нужно дозаполнить в
   `knowledge_base/salary_rules.json`, либо ввести вручную в Excel).
5. Материалы: `smeta_builder.build_materials_table()` с
   `ObjectParams(area_sqm, cleaning_days, general_days, staff_count, contract_months)`
   и прайс-листами из `price_parser.load_general_opt_price_list()` +
   `load_retail_suppliers_manual_additions()` (без скидочных/разовых
   прайсов конкретных объектов, как в старых скриптах — стандартный набор
   для нового тендера). `MaterialsTableResult.unresolved` пробрасывается
   в `warnings` как есть.
6. Сборка `.xlsx`: `Workbook()` + `SmetaSheet.new()` +
   `build_contract_term_section()` → `build_price_summary_section()` →
   строка ФОТ (значение либо editable-плейсхолдер с заметкой) →
   `build_materials_table()`. Порядок разделов — по стандарту из
   `CLAUDE.md` (срок → цена/мес → цена/год → численность → материалы).
7. Сохранение: `output_dir/<slugify(object_name)>_<YYYYMMDD-HHMMSS>.xlsx`,
   директория создаётся при отсутствии.

## Компонент 2 — `app.py` (Streamlit)

- **Вход**: `st.text_input(type="password")`, сравнение с
  `os.environ["APP_PASSWORD"]` (хранится в `.env`, не в git — уже
  настроенный паттерн в проекте). Успешный вход → флаг в
  `st.session_state`, действует до закрытия вкладки/перезапуска процесса.
- **Форма**: `st.file_uploader` (pdf/docx/xlsx), selectbox для региона
  (по умолчанию «Москва» — единственный заполненный в базе),
  selectbox для сложности объекта/графика (по умолчанию — единственная
  существующая комбинация, с пояснением в интерфейсе, что для остальных
  норматив не заполнен), `st.number_input` для ставки НДС (по умолчанию 20%).
- **Запуск**: кнопка «Рассчитать» → `st.spinner(...)` на время вызова
  `generate_smeta()` (вызов Claude API занимает заметное время).
- **Ошибки**: любое исключение из `smeta_pipeline` ловится и показывается
  через `st.error()` с текстом исключения — без падения приложения.
- **Результат**: `st.metric()` для площади/дней/месяцев/численности/ФОТ/
  материалов/цены-в-месяц; `st.warning()` построчно для каждого элемента
  `warnings`; `st.download_button()` с готовым `.xlsx`.

## Поток данных и обработка ошибок (сводка)

```
Пароль → загрузка файла → document_ingestion → (пусто? → ошибка в UI)
  → extract_tz_structured (Claude API, ошибка API → ошибка в UI)
  → process_extraction (нет периодов? → ошибка в UI)
  → get_combined_shift_salary (None? → предупреждение, не ошибка)
  → build_materials_table (unresolved? → предупреждение, не ошибка)
  → сборка .xlsx → сохранение в Outputs/tender-agent-smeta/
  → метрики + предупреждения + кнопка скачивания
```

Главный принцип (соответствует остальному проекту, см. `CLAUDE.md`):
**никогда не выдумывать числа**. Если норматив не найден — явное
предупреждение и editable-плейсхолдер в Excel, а не придуманное значение.

## Тестирование

- `smeta_pipeline.py`: ручная проверка на реальном ТЗ (как уже делалось в
  этой сессии с тестовым фрагментом через живой API) — сверка цифр и
  осмотр `.xlsx` на `#REF!`/`#DIV0!` глазами.
- `app.py`: ручной прогон через `streamlit run app.py` — полный цикл
  загрузка → расчёт → скачивание; отдельно — сценарий с незаполненным
  нормативом (регион/сложность вне единственной существующей комбинации),
  чтобы убедиться, что приложение показывает предупреждение, а не падает.
- Автоматических тестов не вводится (в проекте их нет нигде, см. README).

## Открытые ограничения (переносятся из существующей базы знаний)

- `salary_rules.json` заполнен только для «Москва / стандартный /
  комбинированная смена» — для прочих комбинаций ФОТ потребует ручного
  ввода.
- `staff_norms.json` (800-1200 м²/чел) неприменим к объектам с
  периодической моделью уборки (ГЭСН/затратный метод) и крупным
  промышленным объектам — см. `_scope_warning` в файле.
- Материалы для территории/озеленения — известный пробел (занижение
  сметы ~31% на одном реальном объекте, см. `CLAUDE.md`).

Эти ограничения не блокируют Этап 1 — интерфейс должен их прозрачно
показывать пользователю через `warnings`, а не скрывать.
